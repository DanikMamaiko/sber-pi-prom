# Сквозная регрессия PI-цикла

Дата прогона: 28 июля 2026 года.

## Покрытый поток

- создание и повторное открытие PI-цикла;
- setup: даты, спринты, ПИРы, Agile- и ИТ-проектные команды, компетенции, цели и тэги;
- общий бэклог, отправка и повторная отправка в Pre PI;
- обязательные поля Agile/ИТ-проектов и атомарная публикация на доски;
- редактирование целей с обратной синхронизацией в Pre PI;
- stories, работы, спринты и недели командных досок;
- состав и серверный расчёт ёмкости;
- связи и геометрия Program Board;
- общие, командные и опубликованные командные риски;
- повторные GET всех агрегатов как эквивалент перезагрузки страницы;
- удаление работы, инициативы и команды с проверкой зависимых данных;
- изоляция двух кварталов;
- ошибки 422, отсутствие частичного сохранения и защита legacy POST API.

## Найденные и исправленные дефекты

1. Во время редактирования setup вызовы `save(false)` запускали фоновую запись ёмкости и
   других зависимых агрегатов раньше сохранения команд. Backend закономерно отвечал 422
   «команда не входит в PI-цикл». Теперь `save(false)` сохраняет только состояние экрана;
   нормализованные агрегаты синхронизируются после успешного PUT setup.
2. Pre PI мог создавать глобальную команду из опечатки и использовать её вне текущего PI.
   Теперь владелец, исполнители и команды привлечения обязаны входить в setup цикла.
3. Спринты проверялись только как неотрицательные числа. Теперь backend проверяет границы
   `0..sprint_count-1`, недели и запрет недели без спринта.
4. Компетенции и трудозатраты можно было передать вне настроек команды. Теперь проверяются
   коды, неотрицательные конечные значения и соответствие компетенциям PI-команды.
5. Переданный UUID из другого цикла мог молча заменяться сущностью, найденной по Issue ID/UID.
   Теперь несовпадающие ID инициатив, stories, работ, ёмкости, связей и рисков дают 422.
6. Удаление команды из setup не очищало всех зависимостей. Теперь удаляются её ёмкость,
   командные риски, цели и исполнители, а ссылка владельца инициативы обнуляется.
7. `overview.teams_count` считал глобальный справочник команд вместо состава текущего PI.
   Теперь считается `PiCycleTeam` выбранного цикла.

## Автоматические проверки

- 26 быстрых unit/schema/архитектурных тестов;
- 12 интеграционных сценариев FastAPI на PostgreSQL 16;
- всего 38 pytest-тестов;
- миграции тестовой БД применяются до `20260728_0011`;
- inline JavaScript `frontend/index.html` проходит синтаксическую проверку;
- рабочие контейнеры `api`, `db`, `frontend` здоровы; в свежих логах нет API 5xx или traceback
  (единственный nginx 404 относится к отсутствующему необязательному `favicon.ico`).

Ручная UI-регрессия завершена после пересборки: открыты все семь вкладок Q1, проверены
перезагрузка и повторное открытие цикла, данные setup загружены из нормализованного API,
ошибок frontend-консоли нет. После включения релиза A повторная загрузка не использует
snapshot для полностью инициализированных Q1 и Q2.

После релиза B повторно открыты все вкладки Q1 без чтения snapshot. Заголовок интерфейса
изменён на «Платформа для планирования и бюджетирования»; в отображаемом frontend и его
исходниках больше нет маркировки системы как прототипа.

Релиз C проверен на чистой и существующей PostgreSQL: колонка snapshot отсутствует,
контрольные количества всех нормализованных таблиц совпали до и после миграции, OpenAPI
не содержит snapshot, downgrade/повторный upgrade проверены на тестовой БД, все семь
вкладок Q1 открываются без ошибок консоли.

Optimistic locking проверен отдельным Postgres-сценарием и вручную в UI: первый редактор
увеличивает версию, устаревший PUT/PATCH получает 409 без частичного сохранения, после
перечитывания запрос можно безопасно повторить. Frontend сериализует собственные записи и
показывает одно предупреждение «Конфликт изменений» с требованием перезагрузить страницу.
