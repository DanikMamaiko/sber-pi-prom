# Удаление compatibility snapshot — завершено

Релизы A, B и C выполнены 28 июля 2026 года. Compatibility snapshot удалён из frontend,
SQLAlchemy, Pydantic/OpenAPI и основной PostgreSQL миграцией `20260728_0009`.

## Итоговое состояние

- frontend не читает, не пишет и не импортирует snapshot/sessionStorage business data;
- `PiCycleCreate`, `PiCycleUpdate` и `PiCycleRead` не содержат snapshot;
- OpenAPI не содержит ни одной схемы с полем snapshot;
- таблица `pi_cycles` не содержит колонку snapshot;
- старые запросы с snapshot получают 422;
- источниками истины являются только нормализованные агрегатные API.

## Результат релиза A

- запись отключена во frontend и защищена backend-флагом;
- новые циклы создаются с `snapshot={}`;
- старые snapshot не очищаются и не перезаписываются;
- `STORAGE_VERSION=3`, `state.cycles` удаляется из sessionStorage только после успешной
  загрузки всех нормализованных агрегатов;
- флаги `*_initialized` в `PiCycleRead` определяют, нужен ли fallback;
- оба существующих цикла полностью инициализированы и при повторной загрузке fallback не используют;
- контрольные MD5 snapshot до и после включения режима совпадают;
- проходят 20 тестов и визуальный UI-чек-лист.

Локальные резервные копии исключены из Git:

- `backups/sberpi-20260728-before-snapshot-release-a.dump` — полный custom-format dump;
- `backups/compatibility-snapshots-20260728-before-release-a.json` — два snapshot;
- SHA-256: `4092A26DD285F06667B245726A9C3D5B5AC8C51FCBF207770FC16894C2135C29`
  и `DA0F0E62BD5EDD88CCAE56C7B172300A9561DE6041187FE2D9B89B1E44BFD450`.

## Рекомендуемая последовательность

### Релиз A — выполнен

Все шесть запланированных действий выполнены. Завершённость импорта определяется существующими
флагами `setup/initiatives/goals/boards/capacity/program_board/risks_initialized`; отдельная
дублирующая колонка не потребовалась.

### Релиз B — отключить чтение snapshot

Технические действия выполнены:

1. Оба существующих цикла полностью инициализированы.
2. `loadCyclesFromApi` всегда начинает с `blankCycle()` и заполняет данные нормализованными API.
3. Legacy-import и чтение `rec.snapshot` удалены, `STORAGE_VERSION=4`.
4. Поля snapshot удалены из write DTO; extra-поля запрещены и дают 422.
5. OpenAPI содержит snapshot только в `PiCycleRead`.
6. 20 тестов и UI-проверка всех вкладок проходят; MD5 сохранённых snapshot не изменились.

Старые `/backlog` и `/initiatives/from-backlog` удалены при переводе вкладки «Бэклог»
на канонические команды `/backlog-board`. Legacy `/goals` и `/risks` остаются отдельной
задачей и не используются вкладкой «Бэклог».

### Релиз C — выполнен

1. Миграция `20260728_0009` удаляет `pi_cycles.snapshot`.
2. Snapshot удалён из SQLAlchemy, Pydantic и OpenAPI.
3. Upgrade проверен на чистой и существующей PostgreSQL; downgrade/повторный upgrade также
   проверены на пустой тестовой БД, проходят 20 тестов.
4. До и после миграции совпали количества строк во всех нормализованных таблицах.
5. Повторная UI-проверка всех вкладок Q1 прошла без ошибок консоли.
6. Экспорт и полный dump сохраняются до завершения пилотного окна.

Downgrade `0009` восстанавливает только пустую JSONB-колонку. Историческое содержимое при
необходимости восстанавливается из JSON-экспорта или полного dump, а не из downgrade.

## Выполненные критерии

- все циклы открываются после полной очистки sessionStorage;
- пустые агрегаты не восстанавливаются из старого снимка;
- повторная отправка в Pre PI и на доски идемпотентна;
- удаление работы/инициативы/команды не оставляет связей и скрытых строк;
- два браузера, открывшие разные кварталы, не смешивают данные;
- 21 текущий тест и визуальный чек-лист проходят на чистой и существующей БД;
- есть проверенный JSON-экспорт и процедура отката.

Следующий приоритет после удаления snapshot выполнен: миграция `20260728_0010` добавила
optimistic locking и защиту агрегатов от перезаписи устаревшим клиентом.
