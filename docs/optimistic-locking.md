# Optimistic locking агрегатов

Реализовано 28 июля 2026 года миграцией `20260728_0010`.

## Контракт

- `pi_cycles.version` — общая версия всех связанных агрегатов одного PI-цикла;
- `backlog_board_state.version` — отдельная версия глобального бэклога;
- каждый GET агрегата возвращает `version`;
- каждый PUT/PATCH, а также `backlog/dispatch` и `pre-pi/submit`, требует
  `expected_version`;
- backend блокирует строку версии через `SELECT ... FOR UPDATE`, сравнивает версии и
  увеличивает её в той же транзакции, что и бизнес-изменения;
- устаревший запрос получает HTTP 409 и не изменяет данные.

Пример ответа 409:

```json
{
  "detail": {
    "message": "Aggregate was changed by another editor",
    "aggregate": "pi_cycle",
    "expected_version": 7,
    "current_version": 8
  }
}
```

Frontend хранит версии только в памяти открытой страницы, сериализует собственные
мутации общей очередью и не повторяет конфликтный запрос автоматически. Пользователь
видит предупреждение и должен перезагрузить страницу, чтобы получить актуальные данные.

Legacy POST-методы пока не требуют `expected_version`, но блокируют и увеличивают версию.
Поэтому их изменения также инвалидируют устаревшие редакторы нормализованных агрегатов.
